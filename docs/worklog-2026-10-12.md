## Architecture decisions made during the session

The user chose, at the start: pure Rust on the NativeActivity path (no Kotlin UI, no WebView), minimal feature scope. That choice shaped everything after. When the iOS target came up mid-session, the same constraint carried over: the objc2 bindings rather than a Swift or ObjC shell, even though the bindings route cost roughly a day of extra work.

The workspace split (`1d813c2`) extracted everything platform-independent into `rustnotes-core`: app state machine, UI layout and drawing, word wrap, SQLite storage, the GL renderer. The shells translate platform events into a neutral `CoreEvent` enum and provide a two-method `Platform` trait (show/hide keyboard). Nothing in core knows which OS it is running on; the note logic, the bug fixes, and the renderer are shared byte-for-byte.

Fonts load at runtime from the device — `/system/fonts/Roboto-Regular.ttf` on Android, `/System/Library/Fonts/SFNS.ttf` (San Francisco) on iOS — so the APK/IPA carries no font file and no font licence.

## How the UI was verified

The AI in this session cannot view images, so screenshots were verified by measurement instead of by eye. Two small Python scripts (dependency-free PNG decoders) sampled pixels and scanned rows and columns for colour runs. Every claim below that mentions pixels comes from those measurements, not from looking at the screen.

Examples of what this caught that eyes might have missed: the title band at exactly y 456–509 after the baseline fix, the date and snippet sharing one corner with a 1 px gap, the header starting at y 0 instead of y 159 when an inset failed to apply.

## Bugs found and fixed

In rough order of discovery:

1. **glow 0.14.2 API drift.** Several renderer calls used old signatures (`vertex_attrib_pointer_f32` gained a type argument and reordered others; `buffer_data_f32` became `buffer_data_u8_slice`; `PixelUnpackData` takes an explicit enum). Fixed against the vendored source.
2. **16 KB page alignment.** The first launch triggered Android's "App Compatibility" dialog: `LOAD segment not aligned`. Fixed with `-Wl,-z,max-page-size=16384` in `.cargo/config.toml`. Verified with `llvm-readelf` (all LOAD segments at `0x4000`). The dialog itself is a system window that outlives the app; it reappeared later from a stale install and had to be dismissed by reading the window tree.
3. **Status-bar inset.** `content_rect` reports the full window under NativeActivity, so the + button was untappable under the status bar (cutout inset is 159 px on the test device). Fixed with a one-time JNI query: `WindowInsets.systemBars().top` through `run_on_java_main_thread`, using jni 0.22's `jni_str!`/`jni_sig!` macros.
4. **The same JNI query deadlocks in the wrong lifecycle slot.** Called during `Resume` it blocked forever — the Java thread parks between `poll_events` calls, so `recv()` never completes and the app ANRs on its splash screen. `GainedFocus` worked on one emulator state and never fired on another. Final form: post the query without waiting, drain it with `try_recv` on later loop iterations.
5. **Hardware BACK never arrives** on the API 36 emulator (consumed by the predictive-back dispatcher despite `enableOnBackInvokedCallback="false"`). The on-screen back button covers it; edits autosave regardless.
6. **Two-tap delete disarmed itself.** A stale "disarm" block ran before the confirm branch, so the second tap re-armed instead of deleting. Removed; `take()` in the branch does the job.
7. **Glyph baseline** (spotted by the user: "characters are top aligned"). fontdue's `Metrics.ymin` is documented as the bitmap's *bottom* edge; the renderer used it as the top. Every glyph sat below the line, each offset by its own height. One-line fix; verified by re-measuring (title ink moved from 498–552 to 456–509).
8. **iOS font path.** The loader's candidates were Android paths; iOS has no Roboto. Added `/System/Library/Fonts/SFNS.ttf`.
9. **Wrong renderbuffer constant.** Passed `1` where `GL_RENDERBUFFER` (0x8D41) belongs — storage allocation silently failed, FBO status 0x8cd6, screen showed the view's white background instead of GL content.
10. **CAEAGLLayer grants storage only after window attach.** Allocating at `viewDidLoad` is too early; moved to `viewDidLayoutSubviews`.
11. **GLenum is NSUInteger on iOS.** objc2's debug runtime checks caught the mismatch — `expected type code 'Q', found 'I'` — in `renderbufferStorage:fromDrawable:`. The crash was symbolicated by rebuilding with the debug profile and running `atos` on the crash-report offsets. Declaration changed from `u32` to `usize`.
12. **Re-entrant `RefCell` borrows, twice.** First: `Platform::show_keyboard` re-entered the shell state while `handle_event` still held the borrow. The text field moved to its own thread-local. Second: `resignFirstResponder` synchronously fires the keyboard notification while `close_editor` holds the borrow. The notification now only records a pending value; the frame tick applies it.
13. **`content_bottom` units bug in core**, exposed by the iOS port: it was treated as a y-coordinate instead of an inset height, which made the core believe the usable area ended 102 px from the top. The empty-state text was being drawn under the status bar.
14. **xbuild's bundled NDK tops out at API 33** and its resource-table parser rejects the android-35 `resources.arsc` format. The xbuild path therefore targets SDK 33; the shell-script APK still targets 35. cc-rs also resolves `llvm-ar` by bare name, so `x.sh` puts the NDK on `PATH`.

One more, discovered rather than fixed: the CAEAGLLayer *type* is not re-exported by objc2-quartz-core (only the feature exists), so the layer is created through `class!(CAEAGLLayer)` via `msg_send` and handled as `Retained<CALayer>`.

## Design review (measured)

A review pass using the same pixel tooling, checked against WCAG and Material targets. Passes: title contrast 17.1:1, snippet 4.94:1, all touch targets ≥ 52 dp, spacing on a clean 4/8 dp rhythm, truncation with ellipsis working. Failures found:

- Date text at 2.52:1 (needs 4.5:1), and it shares a corner with the snippet with about 1 px of separation — a collision waiting for longer strings.
- Empty-state hint at 2.34:1.
- No pressed-state feedback anywhere.
- Armed delete signals by colour alone.
- Editor line-height measured about 1.17× (though that measurement predates the baseline fix and is partly an artifact of it).
- "1 notes" pluralisation — fixed during the workspace split.
- No dark mode; bottom inset handling came later with the iOS keyboard work.

The P1 fixes (date placement and contrast, press feedback, a label on the armed delete) remain open. They are layout-constant and draw-call changes; no architectural work.

## What is deliberately not done

- IME composing input. Text arrives as key events on Android and through a hidden `UITextField` delegate on iOS, which covers basic Latin typing. CJK, autocorrect, and emoji are out.
- Accessibility. There is no accessibility tree on either platform; screen readers cannot use the app. This is the main reason this stack is a learning exercise rather than a shipping product.
- iOS device builds compile (`aarch64-apple-ios`) but need a real signing identity; the simulator path is what is verified.
- No animations, no dark mode, no search.
